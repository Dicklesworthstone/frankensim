# Worked example: a cooled enclosure, end to end (as far as the product honestly goes)

This example walks the real `frankensim` CLI over the repository's tracked
reference project — a minimal enclosure with one internal air region, a
bound material card, a declared fan system with vents and leakage, and a
thermal requirement. Every command below is executed continuously by
`scripts/ci/solve_stage_producers_e2e.sh` against exactly these artifacts,
so this walkthrough cannot silently rot: if a command or its expected shape
drifts, that lane breaks.

The example teaches the product's honest boundary as much as its features.
As of this writing the solve pipeline executes a durable four-stage
producer prefix — import-verify, assign, material-resolve, and an
interval-certified flow-network operating point — and then **fails closed
at the conduction stage**, naming the bead that owns the gap. That refusal
is the product working as designed, not a bug: FrankenSim never presents an
incomplete simulator as a working one.

## The artifacts

This example deliberately reuses the tracked fixture rather than shipping a
copy (one set of bytes, one truth):

| File | What it is |
|------|------------|
| `data/reference-project/cooling-reference.fsim` | The canonical project: metadata, versions, seeds, budgets, capabilities, units, geometry receipt, region assignment, material binding, power, cooling (fan-system + vents + leakage), envelope, requirement, solver, outputs |
| `data/reference-project/plate.stl` | The (intentionally tiny) enclosure geometry — a four-facet tetrahedron |
| `data/reference-project/aa6061.fsmcdpk` | The normalized material-card pack the project's binding names by content hash |

The `.fsim` file is canonical s-expression text: one spelling per project,
enforced at parse time. It is regenerated by an in-tree generator test, so
the file and the test fixture cannot drift apart.

## Step 1 — validate

```bash
cargo run -p fs-cli --bin frankensim -- --json validate data/reference-project/cooling-reference.fsim
```

Expected: `"status":"ok"` and `"finding_count":0`, plus the project's
canonical hash. Validation is structural and semantic (mandatory sections,
units and dimensions, duty ranges, requirement sources); it makes no
physics claim.

## Step 2 — import the geometry into a fresh ledger

```bash
cargo run -p fs-cli --bin frankensim -- --json import \
  data/reference-project/cooling-reference.fsim \
  data/reference-project/plate.stl \
  /tmp/cooling-example.db --unit m --max-hole-edges 0
```

Expected: `"status":"ok"` and a FrankenSQLite ledger file at the path you
chose. The import is quarantined: the raw bytes, the promoted mesh, the
import receipt, and the named face groups are all retained as
content-addressed ledger artifacts, and later stages re-attest them rather
than trusting the caller.

## Step 3 — solve (and read the honest stop)

```bash
cargo run -p fs-cli --bin frankensim -- --json solve \
  data/reference-project/cooling-reference.fsim \
  /tmp/cooling-example.db \
  --materials data/reference-project/aa6061.fsmcdpk
```

What you should see, in order, on stderr as JSON progress lines: the four
executing stages complete (`import-verify`, `assign`, `material-resolve`,
`flow-network`), each with an ordinal and a durable ledger receipt. Then
stdout reports:

- `"status":"unavailable"` with `"stage":"conduction"` and
  `"dependency":"frankensim-s93ej"` — the first unimplemented stage,
  named, with the bead that owns it.

How to read what DID happen:

- **material-resolve** bound the project's declared region to the real
  card in the pack you supplied, by content hash — and retained the
  resolved property claims (value, stated uncertainty, validity domain)
  as ledger receipts. A pack that does not supply the declared card, a
  state string at the wrong revision, or a card whose validity is
  narrower than the binding's admitted temperature range each refuse
  with their own named code instead.
- **flow-network** lowered the declared fan curve, vents, and leakage
  area through a sourced sharp-edged-orifice model, derived air density
  from the declared envelope (ideal gas, R = 287.05 J/(kg·K), midpoint
  ambient), and solved an **interval-certified operating point**: the
  retained receipt carries the flow bracket `[lo, hi]`, the pressure
  bracket, and the leakage fraction. "Certified" here means the nominal
  model's root is bracketed by outward-rounded interval arithmetic — it
  does not certify manufacturer tolerances or installation effects, and
  the receipt's no-claim text says so.
- **Run identity** is derived from the project content, the constellation
  and workspace versions, the seeds, and the admitted card-pack set
  root. Re-running the same inputs against a fresh ledger derives the
  same run id; supplying a different pack is a different run.

Resuming is first-class: `frankensim --json solve --resume <run-id>
<ledger>` re-attests the retained stage receipts (byte-identical
re-derivation, not trust) and continues to the same honest stop with no
pack flags at all.

## What this example does NOT show yet

Conduction and QoI extraction refuse as unavailable (owned by
`frankensim-s93ej` and `frankensim-s2l9v`); `report` and `package` refuse
likewise. When those land, this walkthrough extends rather than changes:
the four stages above keep their receipts and their semantics.

For the refusal/fix loop — what it looks like when validation says no —
see `examples/refusal-loop/`.
