# Recover fixed-proposal importance experiments

`ImportanceExecution::checkpoint(model_identity)` and
`ImportanceExecution::restore(plan, proposal, model_identity, bytes)` preserve
completed physical responses and their original likelihood weights. Resume with
the same deterministic evaluator; the next sample keeps the original mixture
component, independent germs, physical transformation and ordinal. Completed
samples are never evaluated again. A failed or nonfinite sample remains terminal
and cannot be saved as an apparently successful prefix.

`FSIMP001` binds every original plan field, including the total call budget,
threshold and input law, plus the defensive fraction, exact ordered shift bits,
model identity and versioned sampler/likelihood semantics. The caller's model
identity must cover all fixed inputs, parameter bindings and executable/runtime
semantics. Changing even an ineffectual shift when defensive mass is one is an
identity change. Other sampler checkpoint formats cannot be interchanged.

The bounded wire format has an 81-byte envelope and 16 bytes per accepted call:
the original QoI and epsilon-scaled likelihood weight, both stored as f64 bits.
Failure flags are derived from the strict original ceiling; unscaled weights
use the same division as the producer. Signed response zero is preserved.
Reports and confidence assessments are reconstructed from ordered observations,
never restored from supplied summaries. Restoring a completed run is terminal,
including when a descriptive statistic is unavailable in finite arithmetic.

Framing, counts, state/budget consistency, checksum and identity are checked
before reserving retained observation storage. Decoding is O(n); it does not
replay sampling or the physical model. Weights must be finite and in their
admitted range, and target-equals-proposal shortcuts must retain their known
constant scaled weight. The original one-million-call cap still applies.

Checkpoints must be trusted. Checksums are not authentication; range checks do
not establish that stored responses or likelihood weights were generated by
the named evaluator or sampler. Recovery creates no physical, statistical,
rounding or cross-runtime validation. No proposal adaptation is permitted in
place. This codec restores one fixed producer, not a `PilotImportanceExecution`
owner with its learning history.

`cargo test -p fs-uq --test product_importance_checkpoint` exercises all prefix
boundaries, singular physical laws, interrupted calls, exact weight/response
bits, confidence parity, immutable identities, malformed payloads and terminal
failures. Native execution is required before claiming a Rust test pass.
